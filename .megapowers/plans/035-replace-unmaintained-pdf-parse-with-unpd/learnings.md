- A dependency swap is most cheaply tested by replacing real-byte parsing with `vi.mock("<lib>", …)` of the named exports — the test then asserts the *contract* (shape, error wrappers) instead of the third-party parse semantics, which keeps PDF tests deterministic without hand-crafting valid PDF bytes.
- Adding a tiny `dependencies.test.ts` that reads `package.json` and asserts `pdf-parse` is absent / `unpdf` is present is cheap, runs in <2ms, and turns "don't reintroduce the unmaintained dep" into a CI-enforced invariant rather than a code-review hope.
- Preserving the outer `try { … } catch (err) { return makeErrorResult(url, \`Failed to extract text from PDF: ${msg}\`) }` shell was the single most important contract during the swap — every downstream test that does `result.error.toContain("PDF")` rides on that wrapper string, not on the library identity.
- `unpdf`'s `extractText(pdf, { mergePages: true })` returns `text: string | string[]` even with `mergePages: true` per its TS types; the `typeof extracted === "string" ? extracted : extracted.join("\n")` narrowing is defensive but necessary to satisfy the compiler and survive future API tweaks.
- Verifying "no init-time fixture reads" needs evidence beyond test-suite green — `grep -RIn "test/data" node_modules/unpdf` and an explicit `node --input-type=module -e "import('unpdf')…"` smoke check give a tangible artifact that the structural defect (the whole reason for the issue) is gone, not just symptom-masked.
- Pre-library guards (size checks before calling the parser) are a quiet win during dependency swaps: the oversized-PDF test stayed library-agnostic and passed untouched, which collapsed one of the three test-rewrite tasks to "verify still green."
